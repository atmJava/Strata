# 移植执行规则（通用版）· v1.1 · 2026-10-25

> 适用于"把参考项目的有用功能移植/集成到本项目"的逐轮推进：任意语言栈、任意功能大小。
> 配置改动、一个补丁、一次测量，都走同一套规则。
> 与上级章程冲突时以上级为准；本文件只能加严，不能放宽。
> 本项目（Strata 多路融合）的适配层见 [`MULTIPATH_RULES.md`](MULTIPATH_RULES.md)。

## 0. 一句话

**每轮只做一件能让一条验收测试从 FAIL 变 PASS 的事；没有 PASS，就不算这轮做了什么。**

## 1. 适用范围

- 适用于：功能移植、行为对齐、配置项落地、测量轮。
- 不占轮次：一次性排查、纯文档整理、只读评审（这些是轮次内的动作，不是"完成"）。
- 测量轮也占一轮，但必须**产出一个判决或解锁**；"只看看数字"按未发生处理。

## 2. 完成定义（DoD）

**单项"采纳"必须四条全真**：

1. **落地**：代码/配置进仓库（默认关或显式 opt-in）。
2. **验收**：一条**真实断言**的测试 **PASS**。`xfail`/`skip`/删断言/只跑一个用例**不算**。
3. **生效**：验证跑的是新东西——版本号、哈希或行为证据；**构建成功不算生效**。
4. **可回退**：命令或快照存在；演练过，或至少逐字节校验过备份。

**目标级完成 = 每项有判决**（搁置需用户同意 + 触发条件 + 证据）**+ 采纳项全过四条 + 验收矩阵全绿 +
环境健康 + 回滚演练过 + 用户确认**。

**明确不算完成**：判决表填满、文档收口、复盘条数、代码合并、构建成功、演示能跑、"基本完成"。

## 3. 每轮门禁（Gate Sheet）

每轮日志条目必须包含下面 11 行，且门禁脚本判 PASS，才允许提交。

```
### Gate（本轮）
- 轮次：R<n>
- 项：<一个代码项；测量轮写"测量：<臂>"；只许一个>
- 验收判据：<可测 + 阈值 + 适用条件>
- 实现：<file:line 或配置键；测量轮写"无">
- 测试：<命令> → PASS
- 生产：<版本/哈希、health、开关；含开工自检：上轮剩余清单>
- 证据：<原始日志路径 + 脚本名>
- 回滚：<命令或快照；演练 是/否>
- 台账：E-<n>
- 剩余未完成项：<n>（逐项列）
- 没测什么：<清单>
```

**机器判据**（脚本逐条检查，任一不过 = 该轮作废）：

1. 11 行缺一 FAIL。
2. `测试` 行必须是 `→ PASS`；出现 `xfail`/`skip`/`FAIL`/`TODO`/`未跑` FAIL。
3. `项` 为空 FAIL。
4. `剩余未完成项` 不以整数开头 FAIL。
5. `实现` 为空且 `项` 不以"测量"开头 FAIL。
6. `证据` 为空 FAIL。
7. `生产` 有变更而 `回滚` 为空 FAIL。
8. `没测什么` 为空 FAIL。

> 门禁是格式检查，不是功能证明；收口时要抽样**人工复跑**测试命令（见 §9）。

## 4. 禁止清单（违反 = 该轮作废，重做）

1. 用判决表 / 文档收口 / 复盘数量当完成。
2. **自行宣布完成**；完成只能由用户确认。
3. `xfail`/`skip`/删断言当通过。
4. "部分采纳 / 搁置"当交付（搁置需用户同意 + 触发条件 + 数据）。
5. 为让目标可完成而**缩小范围**（改清单、拆项合并、降阈值、改判据都算）。
6. 改验收判据让测试变绿（除非先证明原判据错，并记录理由）。
7. 提交没做过的测量；数字不带条件（环境/版本/并发/冷热）。
8. 一轮改多个代码项或多变量。
9. 把没跑的测试说成通过。
10. 在无效环境里验过就宣布生效。

## 5. 每轮六步

1. **自检**：环境 health、版本/哈希、上轮剩余清单与"下一轮第一件事"。
2. **计划**：假设、臂、判据与阈值、回滚；**先想清楚"结果为 0 怎么办"**。
3. **执行**：一次只改一个变量；快照 → 装 → 测 → 保留或恢复。
4. **测量与验证**：按 §6 的证据规则。
5. **复盘 + Gate**：按 §11 模板；没写 = 本轮按未发生处理。
6. **归档**：台账一条、状态文件一行"下一轮第一件事"；门禁 PASS 才提交。

## 6. 测量证据

- **三件套**：原始日志路径 + 脚本名 + "没测什么"；缺一件按无证据处理。
- **先量仪器**：计时/采样开关本身有代价，开与不开分开比。
- **噪声地板**：项目口径未给时，<3% 不下结论；跨重启/跨会话只作趋势。
- **重复**：每臂 ≥3 次，报中位与离散度；n=1 必须标 n=1。
- **对照**：同会话 A-B-A 或交错；不跨天比。
- **恢复**：逐字节校验（哈希/`cmp`）。
- **不自污染**：测量期间不并行干重活、不派子代理。
- **静态结论**：读代码得出的判断必须标"静态阅读，未测"。

## 7. 预算与回滚

- **每轮重启 ≤2 次**；第 3 次在复盘里写理由。
- **构建/下载单独计**；构建成功 ≠ 部署成功（先产物哈希，再部署路径哈希）。
- **覆盖运行中文件**用新文件 + 原子替换（`cp … .new && mv -f`）。
- **装前快照、装后核对、测后恢复比对**。
- **一个安装器**：动手前确认没有残留进程。
- **生产默认路径逐字节不变**；新行为默认关；实验臂独立目录。

## 8. 阻塞

- 把阻塞降级成"能给出事实的最小实验"。
- 记四件：现象与复现 / 已排除什么 / 需要什么 / 能否绕过。
- **阻塞不是完成**，不减剩余计数。
- 同一阻塞连续 3 轮无进展：上报用户，给两个方案（绕过 / 接受）。
- 搁置按 §4.4。

## 9. 收口与确认

1. 交**验收清单**：项 / 判据 / 命令 / 结果 / 证据 / 台账 / 生产 / 剩余。
2. 全绿 + 环境健康 + 回滚演练过，**才允许**提"完成"，并**等用户确认**。
3. 同时列"未做/搁置"及理由，不得隐藏；搁置项必须有触发条件。
4. 差一项就继续下一轮，不许"基本完成"；用户未确认则目标保持开着。
5. 收口前抽样**人工复跑**至少一条测试命令（防止只写不跑）。

## 10. 文档落点（角色名固定）

| 内容 | 文档 |
|---|---|
| 做什么、顺序、臂 | `PLAN.md` |
| 术语、阈值、矩阵、命名 | `STANDARD.md` |
| 规则、Gate 模板 | 本文件 |
| 每轮复盘 + Gate（最新在上） | `ROUND_LOG.md` |
| 结论与数字 | `EVIDENCE.md` |
| 状态、决策、回滚 | `HANDOVER.md` |

一处一事；日志只给证据路径，不重复结论。

## 11. 复盘模板

```
R<n> · <日期> · <一句话>
- 改了什么：<diff 摘要 + 文件；没改写"无">
- 数字：<臂 / 中位 / 离散度 / N / 冷热 / 判据>；判决：<采纳/否决/未定/参考>
- 预期被推翻：<原以为……实测……；没有写"无">
- 自检：health / 版本 / 上轮剩余清单 / 上轮"下一轮第一件事"
- 预算：重启 <n>（≤2）、停机 <s>、构建 <n>；超支原因
- 没测什么：<清单>
- 下一轮第一件事：<一句>
### Gate（本轮）
- 轮次 / 项 / 验收判据 / 实现 / 测试（→ PASS）/ 生产 / 证据 / 回滚 / 台账 / 剩余未完成项 / 没测什么
```

**例子**（占位符，无真实项目信息）：

```
R7 · 202X-XX-XX · 配置项 <A> 落地
- 改了什么：<配置文件>:<行> 新增 <键>=<值>，默认关
- 数字：<臂A> 中位 12.3 s vs <臂B> 14.1 s（n=3）；判据 ≤13 s → 未过（不采纳）
- 预期被推翻：原以为 A 更快；实测慢 13%
- 自检：health 200 / 版本 <sha256> / 上轮剩余 3 项
- 预算：重启 1、构建 0
- 没测什么：N>4 的并发
- 下一轮第一件事：重测 A 的 N=6
### Gate（本轮）
- 轮次：R7
- 项：配置项 <A>
- 验收判据：<臂> 中位 ≤13 s
- 实现：<配置文件>:<行>
- 测试：`pytest tests/test_<a>.py` → PASS
- 生产：health 200，版本 <sha256>，开关=1
- 证据：<日志路径>，脚本 <脚本名>
- 回滚：恢复快照 <路径>（演练 是）
- 台账：E-42
- 剩余未完成项：2（<B>、<C>）
- 没测什么：N>4
```

## 12. 24/7 无人值守协议（v1.1）

§1–§11 是"有人盯着"的纪律；无人值守还要下面这些，否则会漂、会卡、会停不下来。

1. **队列驱动**：唯一事实源是 `WORK_QUEUE.md`；每轮取队首一项。**删未完成项、降判据 = 违规**；
   新增"发现项"可以，标 `[发现]` 并写进日志，里程碑交用户裁决。
2. **轮次时间盒**：每轮 ≤45 min。到点必须 checkpoint：更新 `STATE.md`、队列、日志；**不许把半成品**
   （改了没测、装了没验、备份没恢复）留在生产上过夜。
3. **三段式**：准备（preflight：health + 队列/STATE 一致，以 `tools/server/preflight.py` 实际检查为准；
   备份、磁盘、版本随四问人工核）→ 执行（一项）→ 验收（测试 +
   独立复核）。
4. **独立复核**：每项标"已完成"前，派一个**只读子代理**按验收判据复核证据（不看结论看证据）；
   复核不过 = 未完成。复核不占轮次、不算测速。
5. **自更新边界**：允许改顺序、改方法、加发现项；**不允许**改判据、删项、把未完成标完成。
   每次自更新在日志写一行"为什么改"。
6. **熔断**：同一项连续 3 轮失败 → 停该方向，换方案或上报；生产 health 连续 2 次失败 → 立即恢复并停轮；
   跨轮日重启累计 ≤6 次，超了停一天做复盘。
7. **证据归档**：每轮证据放 `/opt/ai/logs/<round>-*`；台账一条；日志只留路径。
8. **交接**：每 10 轮写一次 HANDOVER 摘要；上下文压缩/会话重启后先读 `STATE.md` 再动手。
9. **停机条件**（只有这三种，其余继续下一轮）：队列清空（交验收清单，等用户确认）；熔断触发；用户叫停。
10. **里程碑汇报**：每完成 3 项或每 10 轮，给用户一页摘要（完成/未完成/风险/下一步），不打断连续执行。

> 无人值守 ≠ 无人负责：里程碑汇报 + 熔断上报是"人在环上"，不是"人盯着"。
