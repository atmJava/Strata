## 2. 每轮循环（选什么）

1. **读指标**：找**差距最大**的那一项（不是"队列下一项"）。
2. **假设**：可证伪的一句话 + 预期收益 + 验收判据（数字/阈值/条件）。
3. **实验**：同 boot A-B（每臂 ≥3，中位+离散度）或交错；一次一个变量。
4. **保留/回滚**：达到判据（≥3% 或门槛）→ 保留、更新基线；否则回滚并记否决（否决也留档）。
5. **落账**：指标表、台账、日志 Gate。
6. **没有高价值假设时**（backlog 空或全部低价值）→ 走 §4 发现轮；仍没有 → 报告用户请求方向
   （不是"完成"）。

## 3. Backlog 永不枯竭

来源：① 指标回归；② 审计发现（fork/引擎开关/依赖）；③ 引擎 env/flags 扫描；④ fork 新特性；
⑤ 用户需求；⑥ 模型/硬件/驱动变化。

- 每项：瓶颈、假设、预期收益、成本、风险、验收判据。
- 状态：`待做` / `进行中` / `已完成` / `否决`；新增标 `[发现]`，删除需用户同意。
- **"已完成"只给真正采纳并生效的改进**；否决项保留，防重踩。

## 4. 发现轮（backlog <3 或每 5 轮）

只读子代理（不改生产、不跑服务）做一件事：找**下一个能改善 M1–M9 的机会**。产出候选表
（预期收益/成本/风险/验收）。主会话筛选入 backlog；**发现轮不占改进轮的 Gate**，但要有报告。

## 5. 停机条件（只有这三种）

1. **用户叫停**（唯一正常的"结束"）。
2. **熔断**：生产 health 连续 2 次失败；或跨轮日重启 >6；或同一假设连续 3 轮失败。
3. **连续 3 个发现轮没有 ≥3% 的候选** → 报告用户，请求换方向/换指标（仍不叫"完成"）。

## 6. 防漂移

- 指标/基线只由测量更新；改判据需用户同意并写日志。
- 每个改进"保留或回滚"二选一，不留半开状态。
- 每 5 轮给用户一页指标对比（M1–M9 表 + 保留/否决清单 + 下一步）。
- Gate 照旧：没有 PASS 的验收测试就不算这轮做了什么。
