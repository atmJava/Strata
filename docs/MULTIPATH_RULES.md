# 多路融合执行规则（MULTIPATH_RULES）· v0.2 · 2026-10-25

> 上级章程是 [`RULES.md`](RULES.md)（怎么干活、决策权、证据规则）。本文件只补**多路融合执行中**的规矩：
> 每轮门禁、完成定义（DoD）、禁止清单、复盘模板、预算、测量卫生、子代理、升级生产、文档落点。
> **与 `RULES.md` 冲突时以 `RULES.md` 为准；本文件只能加严，不能放宽。**
>
> **为什么有 v0.2**：v0.1 把"判决表写满 / 文档收口"当成了完成，结果两次在**采纳项没实现**时停了工
> （见 §9）。v0.2 的唯一目的是：**让"停"在规则上不可能**——没有 PASS 的验收测试，就没有"这轮做完了"。

## 0. 一句话

**每轮只做一件能让验收测试从 FAIL 变 PASS 的事；没有 PASS，就不算这轮做了什么。**

## 1. 完成定义（DoD，任何"采纳"项必须四条全真）

1. **落地**：代码/配置进仓库（默认关或显式 opt-in），生产可装。
2. **验收**：一条**真实断言**的测试 **PASS**；`xfail`/`skip` **不算**。
3. **生效**：装上生产并验证（opt-in 项：启用步骤写清、演练过、机器可复查）。
4. **可回退**：回滚命令/快照存在；演练过，或至少逐字节验证过备份文件哈希。

**目标完成 = 所有采纳项满足 DoD + 多路验收矩阵（`MULTIPATH_STANDARD.md` §1）全绿 + 生产健康 +
回滚演练过 + 用户确认。** 判决表、文档收口、复盘数量，都不是完成依据。

## 2. 每轮门禁（Gate Sheet，写进 LOG 才算这轮存在）

每轮 `MULTIPATH_LOG.md` 的条目**必须**包含下面这块，且 `tools/server/round_gate.py` 必须判 PASS：

```
### Gate（本轮）
- 项：<ID>（≤1 个代码项；测量轮写测的臂与判据）
- 验收判据：<可测、含阈值>
- 实现：<file:line / config / "无（测量轮）">
- 测试：`<命令>` → PASS（xfail/skip 记 FAIL）
- 生产：<health / 版本 / md5 / 是否生效>
- 台账：L-xxx
- 剩余未完成采纳项：<n>（逐项列）
```

**启动自检（每轮开头，写进"生产"行）**：生产 health、当前引擎/server md5、`HANDOVER.md` 顶部状态、
上轮"剩余未完成采纳项"清单。答不上来就先查，再动手。

**测量轮**：允许不做代码，但必须**产出一个判决或解锁**（例如"这个开关在生产不触发，W2 否决"）；
只"看看数字"的轮次按未发生处理。

## 3. 禁止清单（违反 = 该轮作废，重做）

1. 用判决表 / 文档收口 / 复盘数量当完成。
2. **自行 complete**；完成只能由用户确认（`update_goal complete` 前必须先交 §8 的验收清单）。
3. `xfail` 当通过；"部分采纳 / 搁置"当交付（搁置需**用户同意** + 触发条件 + 数据）。
4. 为了让目标可完成而**缩小范围**（改目标/改清单/降判据都算）。
5. 改验收判据让测试变绿（除非先证明原判据错，并记录理由）。
6. 提交没做过的测量；数字不带条件（机型/版本/并发/冷热）。
7. 一轮改多个代码项（拆轮；每项独立测试）。
8. 把没跑的测试说成通过。

## 4. 每轮六步（沿用 v0.1，强制 Gate）

1. **事前审查**：查台账索引、`MULTIPATH_LOG`、引擎自带开关；能不能免停机；影响面（谁在用、回滚成本、重启次数）；
   要改的源码核实到行。
2. **计划**：假设、臂、判据、回滚命令；**先想清楚"结果为 0 怎么办"**。
3. **执行**：一次只改一个变量；快照 → 装 → 测 → 恢复/保留（按 §6）。
4. **测量与验证**：同 boot A-B-A 或交错、每臂 ≥3 次、中位+sd；原始日志 + 脚本名；恢复后 `cmp -s`。
5. **复盘**（本轮必做）：按 §5 模板 + §2 Gate；写进 `MULTIPATH_LOG.md`；**没写 = 本轮按未发生处理**。
6. **归档**：台账一条、`HANDOVER.md` §13 一行"下一轮先做"、相关服务器文档；`round_gate.py` 判 PASS 才 commit。

## 5. 复盘模板（每轮必填，缺一项都不算完成）

```
R<n> · <日期> · <一句话>
- 改了什么：<diff 摘要 + 文件；没改就写"无">
- 数字：<表：臂 / 中位 / sd / N 路 / 冷热 / 判据>；判决：<采纳/否决/未定/参考>
- 预期被推翻：<"我们原以为……，实测……"；没有就写"无">
- 四问：① cron/timer 在跑吗 ② 有残留进程吗 ③ /opt/ai/logs/vram-perf.csv 有漂移吗 ④ 方向要不要调
- 预算：重启 <n> 次（上限 2）、停机 <s>、构建 <n> 次；超支原因：<有就写>
- 没测什么：<清单>
- 下一轮第一件事：<一句>
### Gate（本轮）
- 项 / 验收判据 / 实现 / 测试（PASS/FAIL）/ 生产 / 台账 / 剩余未完成采纳项
```

**四问**（沿用 `RULES.md` §8）：cron/timer 是否在跑、有没有残留进程、`vram-perf.csv` 有没有漂移、方向要不要调。

## 6. 重启与停机预算

- **每轮默认 ≤2 次重启**；第 3 次要在复盘里写明理由，由会话决定。
- **构建单独计**：一次构建 ≈10.6 min；构建后先 `md5sum` 产物、再验部署文件，两者一致才启动；
  覆盖运行中的二进制只许 `cp … .new && mv -f`。
- **低峰窗口**做重启类实验；动手前 `pgrep -af "[u]se-config|[r]estore-prod"` 必须为空（一个安装器）。
- 装前 `cp -p` 快照；装完 `verify-running-config.sh` 核；测完装回快照并 `cmp -s`。

## 7. 测量卫生

- **不自污染**：测量期间本会话不生成、**不派子代理**；后台任务发起后立刻 `job_output wait` 阻塞等。
- **先量仪器**：`STRATA_*_TIMING` 自身有代价（L-030：+2.5–8%）；开计时器的臂与不开的臂分开比。
- **噪声地板**：<3% 不结论；跨 boot 只作趋势；小读/首字跨 boot 按 ~7%（L-031）；4 路跨 boot 曾到 9%（L-040）。
- **三件套**：原始日志路径 + 脚本名 + "没测什么"；缺一件按无证据处理。
- **单次数字标 n=1**，不能当结论。

## 8. 收口与确认（提完成的唯一方式）

1. 交**验收清单**：每采纳项 / 测试命令 / 结果（PASS）/ 台账 / 生产状态。
2. 全部 PASS、多路矩阵全绿、生产健康、回滚演练过，**才允许**提"完成"，并**等用户确认**。
3. 提完成时**同时列**"未做/搁置"及理由，不得隐藏；搁置项必须有触发条件。
4. 任何一项没 PASS 就继续下一轮，不许以"基本完成"收口。

## 9. 事故复盘（为什么有 v0.2）

- **2026-10-24/25 两次提前停工**：第一次 11 项里 5 项"部分采纳/搁置"就标完成；第二次"补判决"目标下
  12 项采纳的 S 项零代码就标完成。根因：① 完成定义错（判决=完成）；② 被质疑时缩小目标；③ `xfail` 当绿。
- v0.2 的 §1（DoD）、§2（Gate）、§3（禁止）、§8（用户确认）是针对性补丁；`tools/server/round_gate.py`
  是它的机器检查。

## 10. 子代理规则

- 子代理也是这台服务器上的第二路流：有子代理在跑时，**不在这台机器上测速度**。
- 只做只读工作；产出由主会话复核后进文档；推断标"静态阅读，未测"。

## 11. 升级生产

- 唯一入口 `use-config.sh`；装完 `verify-running-config.sh`；回滚命令随预设一起记录。
- 新预设先跑完 `MULTIPATH_STANDARD.md` §2.6 的矩阵，全绿才进 `HANDOVER.md` §3 决策表。
- 代码臂（W3 等）进独立 build 目录，默认关；生产 `build/strata` 一字节不动；回退 = 换路径 + 一次重启。
