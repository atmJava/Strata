# 多路融合执行规则（MULTIPATH_RULES）· v0.1 草案 · 2026-10-24

> 上级章程是 [`RULES.md`](RULES.md)（怎么干活、决策权、证据规则）；本文件只补**多路计划（W1–W4）执行中**的规矩：
> 每轮流程、复盘模板、预算、测量卫生、子代理、升级生产、文档落点。
> **与 `RULES.md` 冲突时以 `RULES.md` 为准；本文件只能加严，不能放宽。**
> 配套：[`MULTIPATH_PLAN.md`](MULTIPATH_PLAN.md)（做什么）、[`MULTIPATH_STANDARD.md`](MULTIPATH_STANDARD.md)（口径）、
> [`MULTIPATH_LOG.md`](MULTIPATH_LOG.md)（每轮复盘记录）。

## 1. 每轮六步（比 `RULES.md` §2 多一步"复盘"，不可跳）

1. **事前审查**：这件事做过没有（先查台账索引、`MULTIPATH_LOG`、上游/引擎自带开关）；能不能免停机；
   影响面（谁在用、回滚成本、要几次重启）；要改的那段源码核实到行。
2. **计划**：写清假设、臂、判据、回滚命令；**先想清楚"如果结果为 0 怎么办"**（是记否决、降级，还是换判据）。
3. **执行**：一次只改一个变量；快照 → 装 → 测 → 恢复（`RULES.md` §9、`tools/server/README.md` 的固定形状）。
4. **测量与验证**：同 boot A-B-A 或交错、每臂 ≥3 次、中位+sd；原始日志 + 脚本名；恢复后 `cmp -s` 逐字节验证。
5. **复盘（本轮必做）**：按 §2 模板填，写进 [`MULTIPATH_LOG.md`](MULTIPATH_LOG.md)；**复盘没写 = 本轮按未发生处理**。
6. **归档**：台账一条、`HANDOVER.md` §13 一行"下一轮先做"、相关服务器文档（运维相关时）。

## 2. 复盘模板（每轮必填，缺一项都不算完成）

```
R<n> · <日期> · <一句话>
- 改了什么：<diff 摘要 + 文件；没改就写"无">
- 数字：<表：臂 / 中位 / sd / N 路 / 冷热 / 判据>；判决：<采纳/否决/未定/参考>
- 预期被推翻：<"我们原以为……，实测……"；没有就写"无">
- 四问：① cron/timer 在跑吗 ② 有残留进程吗 ③ /opt/ai/logs/vram-perf.csv 有漂移吗 ④ 方向要不要调
- 预算：重启 <n> 次（上限 2）、停机 <s>、构建 <n> 次；超支原因：<有就写>
- 没测什么：<清单>
- 下一轮第一件事：<一句>
```

**四问**（沿用 `RULES.md` §8）：cron/timer 是否在跑、有没有残留进程、`vram-perf.csv` 有没有漂移、
方向要不要调。任何一项答不上来，先去查再收尾。

## 3. 重启与停机预算

- **每轮默认 ≤2 次重启**（一次 A 恢复、一次 B 安装；A 臂现跑着不装）。第 3 次要在复盘里写明理由，
  由会话决定，且在下一轮把预算调回来。
- **构建单独计**：一次构建 ≈10.6 min（`tools/server/README.md`）；构建后先 `md5sum` 产物、再验部署文件，
  两者一致才启动；覆盖运行中的二进制只许 `cp … .new && mv -f`。
- **低峰窗口**做重启类实验；动手前 `pgrep -af "[u]se-config|[r]estore-prod"` 必须为空（一个安装器）。
- 装前 `cp -p` 快照；装完 `verify-running-config.sh` 核；测完装回快照并 `cmp -s`。

## 4. 测量卫生

- **不自污染**：测量期间本会话不生成、**不派子代理**；后台任务发起后立刻 `job_output wait` 阻塞等
  （`HANDOVER.md` §7/§9.16）。
- **先量仪器**：`STRATA_*_TIMING` 自身有代价（L-030：+2.5–8%）；开计时器的臂与不开的臂分开比。
- **噪声地板**：<3% 不结论；跨 boot 只作趋势；小读/首字跨 boot 按 ~7%（L-031）；4 路跨 boot 曾到 9%（L-040）。
- **三件套**：原始日志路径 + 脚本名 + "没测什么"；缺一件按无证据处理。

## 5. 子代理规则（用户 2026-10-24 要求；沿用 HANDOVER §9.16）

- **子代理也是这台服务器上的第二路流**：有子代理在跑时，**不在这台机器上测速度**（单流会被腰斩）。
- 子代理只做**只读**工作：读参考仓库、核对源码、审文档；不改生产、不跑引擎、不碰服务器。
- 子代理的产出必须由主会话**复核后**才能进文档或台账；结论标来源（file:line），推断标"静态阅读，未测"。
- 需要"边测边分析"时，先停子代理再测；测完再派。

## 6. 失败与止损

- **实验失败且无证据 = 未发生**（不进台账）；有证据 = 记否决，并写清"没测什么"。
- **同一个坑不重踩**：先查台账索引与 `MULTIPATH_LOG`，再决定要不要做。
- **连续两轮没有新事实** → 把问题降级成"能给出事实的最小实验"，在复盘里写清为什么降级。
- 任何一轮若把服务搞到不可用，先按 [`SERVER_RECOVERY.md`](SERVER_RECOVERY.md) 恢复，复盘里写停了几分钟。

## 7. 升级生产

- 唯一入口 `use-config.sh`；装完 `verify-running-config.sh`；回滚命令随预设一起记录。
- 新预设先跑完 `MULTIPATH_STANDARD.md` §2.6 的矩阵，**全绿才进** `HANDOVER.md` §3 决策表。
- 代码臂（W3）只进独立 build 目录，默认关；生产 `build/strata` 一字节不动；回退 = 换路径 + 一次重启。
