# AGENT-SERVER-BREAKDOWN：1/2 路热缓存与冷首轮成本

日期：2026-10-31

状态：同服务诊断完成，用于选择下一项；不是候选性能判决。

## 方法

使用 `tools/server/probe-agent-sessions.py` 对现役 B4 发送 1/2 路 Agent 形状请求：

- 上下文目标约 8K token，实际 prompt 约 12K；
- 1/2 路各 3 波、每波 2 轮；
- 第二轮为同会话续轮；
- 输出上限 64 token，模型实际主要回答 `READY/CONTINUE`；
- 18 个请求全部成功，`foreign=0`。

TTFT 为 `7.336 s`。2 路续轮 TTFT 中位 `2.200 s`，`slot_wait_ms` 中位 `1.479 s`。

## 解释

- 对短 Agent 输出，decode 不是当前大头；热续轮的主要成本是约 `1.4–1.5 s` 的 prompt
  固定/恢复路径，cold 首轮则约 `7.3 s`。
- 1 路首轮与 2 路 prompt 中位相同，但 2 路 wall/TTFT 增加约一倍，主要由槽位等待造成。
- 该测试输出只有 2–3 token；真实推理/长工具调用仍可能由 decode 主导，不能用这组结果
  否定 decode 优化。
- 这是同一服务上的请求 timing，不是客户端 token 统计的换算，也不证明任何候选改善。

uncached token 和准入等待，找一个保守整任务收益 ≥1% 的机制；上界不足则不构建、不重启。
