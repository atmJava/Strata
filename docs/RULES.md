# AI 自主优化协议（RULES）· v2.0 · 2026-10-25

> 这是唯一的执行规则。`PORTING_RULES.md` 和 `EVERGREEN_LOOP.md` 只保留为旧链接的跳转页。
> 目标不是让 AI 填满流程，而是让 AI 持续做出更好的技术决策，独立完成实验、复盘和下一轮选择。

## 1. 授权边界

AI 负责整个优化循环，包括：

- 发现问题、排列路线、提出假设和选择实验；
- 修改代码、配置、测试和文档；
- 构建、部署、重启、测速、回滚；
- 根据证据采纳、否决、重试或换方向；
- 更新工作队列、当前状态、证据和复盘。

在项目范围内，不因取舍、技术风险、实验失败或验收结果向用户请示。AI 自己选择当前最好的路线并记录理由。
只有缺少无法自行取得的外部资产/权限，或需要执行明显超出项目范围且不可恢复的操作时，才报告阻塞；
同时继续做不受阻塞影响的高价值工作。

用户可以直接改变目标或叫停。除此之外，AI 不自行宣布整个优化目标完成。

## 2. 优化目标

决策按以下顺序服务用户价值：

1. **正确、安全、可靠**：不牺牲输出正确性、数据安全或服务可恢复性换性能。
2. **用户可感知的结果**：任务完成时间、首 token、并发吞吐、延迟稳定性、成功率和资源占用。
3. **长期可维护性**：优先复用现有机制，避免为微小收益增加不可回滚的复杂度。

当前指标、基线、目标值和候选路线在 [`ROADMAP.md`](ROADMAP.md)。指标只由测量更新；没有测量的推断必须标明。

## 3. 路线选择

工作队列是候选组合，不是必须从第一行执行的命令。AI 每轮重新判断“现在做什么最值得”。

候选路线至少按五项比较：

- 预期用户收益；
- 成功概率与现有证据；
- 信息价值：能否排除关键不确定性或解锁后续实验；
- 时间、构建、部署和停机成本；
- 风险与回滚成本。

近似排序：

```text
优先度 ≈ 用户收益 × 成功概率 × 信息价值 / (时间 + 部署成本 + 风险)
```

不要求把它算成虚假的精确分数。实际决策遵守这些原则：

1. 先排除不可测量、无用户价值或明显不可回滚的路线。
2. 证据少时，优先做**最便宜且最能区分假设**的实验。
3. 已有强证据和明确收益时，投入更大的工程改动。
4. 两个候选接近时，选更简单、更快、更容易回滚的那个。
5. 每轮记录“为什么选它、为什么不选另外两三个”。
6. 连续在低价值队列项上打转时，主动做发现轮、审计代码或重新定义问题。

## 4. 单次迭代

一次迭代可以从一个指标、异常、代码审计或用户需求开始，到形成可复核结论为止。

1. **定位**：读 `STATE.md`、最近两次复盘、相关台账和代码；确认当前生产形态与真实瓶颈。
2. **列路线**：存在真实选择时，至少比较两三个可行方向，不用“队列第一项”代替判断。
3. **立契约**：动手前写清假设、预期结果、成功阈值、停止阈值、测量方法、回滚方法和主要风险。
4. **准备**：先做代码核实、工装、探针、基线、快照和测试；优先复用现有脚本和开关。
5. **执行**：一次完成相互耦合的改动，再统一构建和测试；不同假设要能通过独立开关或分组实验归因。
6. **验证**：正确性、性能、稳定性和生产生效证据都要看。构建成功不等于部署成功。
7. **判决**：`采纳 / 否决 / 未定`。`未定` 必须说明缺什么信息，并选择补测、换测法或放弃。
8. **复盘**：写 `ITERATION_LOG.md`，更新 `EVIDENCE_LEDGER.md`、`WORK_QUEUE.md` 和 `STATE.md`。
9. **继续**：立即选择下一轮最高价值路线；不等待用户批准。

没有固定 45 分钟或“每轮只能一个文件”的形式限制。批次、时长和并行度由预期收益、归因清晰度和资源竞争决定。

## 5. 实验设计

- 先量当前基线，再改东西；基线和新结果使用相同模型、并发、上下文、冷热状态和版本口径。
- 优先同 boot 交错或 A-B-A；每臂至少 3 次并报告离散度。n=1 只能作探索，不能作定论。
- 低于项目噪声地板的差异不宣称提升；4 路跨 boot 噪声约 9%，同会话通常按 3% 判断。
- 性能实验必须同时检查正确性；配置实验要验证实际运行配置，代码实验要验证实际运行文件。
- 探针本身有成本时先量探针代价。测速期间不运行竞争负载、不派子代理、不并发构建。
- 原始日志、脚本、命令和“没有测什么”必须可追溯；不提交没做过的测量。
- 负结果和失败实验必须留档，它决定下一轮不重复哪条路。

## 6. 复盘

每次形成判决后立即复盘。复盘必须回答“发生了什么、为什么、改变了什么认识、下一步做什么”，而不是重复日志。

```markdown
## I-<日期>-<序号> · <一句话结论>
- 目标 / 指标：
- 假设与预期：
- 为什么选这条路线：
- 改动与实验：
- 结果：基线、变化、样本数、噪声、正确性
- 判决：采纳 / 否决 / 未定
- 预期被推翻：
- 生产状态与回滚：
- 证据：命令、原始日志、脚本
- 学到什么：
- 下一步与理由：
```

复盘的价值在于更新模型；只填字段、不解释结果不算复盘。

## 7. 决策与转向

- 达到预先写下的成功阈值，且正确性与回滚条件满足，才采纳。
- 结果反向、质量下降或风险不可接受，就否决并恢复。
- 未达到阈值但仍有高信息价值，可以补测；没有新信息就停止这条路线。
- 同一假设连续两轮失败，默认换假设或换机制，不重复同形实验。
- 连续三轮核心指标没有实质提升，暂停局部微调，做发现轮或结构性换路。
- 生产健康失败时先恢复服务，再分析；不让实验污染继续累积。

## 8. 生产安全

- 修改生产前留带时间戳快照；一次只运行一个安装/部署操作。
- 运行中的文件用新文件加原子替换；改后核对真实运行文件、配置和版本。
- 部署后检查 `/health`、关键日志和实际生效参数；失败立即恢复并保留证据。
- 测量时避免后台任务、并行构建和子代理污染结果。
- 不把凭据写入仓库或文档；上游仓库保持只读，不向上游提交。
- 删除或覆盖不可恢复数据前验证绝对路径、引用和备份；范围不清楚时停下来询问。

## 10. 完成后状态

一次迭代完成的条件是：有可复核结果、有明确判决、生产安全、证据已落盘、复盘已写、下一步已选。
整个优化目标只有在用户叫停或用户明确确认时结束；队列清空、计划做完或暂时没有好想法都不是结束理由。
