## 1. 目标（三层，胜负从上往下判）

| 层 | 指标 | 为什么在这个位置 |
|---|---|---|
| **L1 任务级** | 真实 agent 任务的**完成墙钟中位**，配思考 token 数、空答案率、工具调用通过率 | 你自己的记录里唯一两位数收益来自这层（思考量 −64% → 墙钟约 −25%，§21.2），而所有引擎开关合计 <5%（§16.5 全在噪声内） |
| **L2 服务级** | 4 路聚合 decode、TTFT p50/p90、并发下的最长 stall 分布 | 这台机器的用途是多会话服务；单机总量与单流是两件事（§12：单流到不了 100，机器总量可以） |
| **L3 单流** | 单流 decode tok/s | 有用但是最弱的一层，不能单独作为采纳依据 |
| **L0 护栏** | VRAM 余量、available RAM、挂起/恢复可靠性、NVLink Replay/Recovery、盘余量 | 不是目标，是硬约束的守门员（§3） |

**要求**：任何优化实验开工前必须写明它动的是哪一层；只写"提速"不写层级的实验不开。

## 2. 判据（沿用现有，不许放宽）

- 同 boot **A-B-A 或交错**；每臂 ≥3 次；报中位 + sd；**<3% 不结论**（本机跨 boot 漂移可达 5%）。
- 跨 boot 的读数只用于看趋势，不用于采纳。
- 改数值的路径必须过**逐位门**（同配置下 512 token 产出同一段）或 KL 质量门，选一个并写明配置要求
  （上游对逐位门的要求：`STRATA_IQ_MT_MIN=1`、`--pcie-frac 0`、固定 adaptive、`--no-prefill-borrow`）。
- 每个实验结束必须落一条台账（§8.2）：boot 标识、命令、原始日志路径、结论（采纳 / 否决 / 未定）、回退方式。
- 读代码得到的结论一律标 *静态阅读，未测*。

## 4. 上游兼容契约（"兼容上游"的具体含义）

1. `main` = 上游，**只允许 fast-forward**。现状已核：`main` = `7ddc17a3` = `upstream/main`。
2. **一个分支一个改动**；每个上游 release 后逐分支 rebase。delta 要短到一眼看完：
   `git log upstream/main..HEAD` 的提交数建议 ≤5，超了就是有人在分支上顺手做了别的事。
3. **配置优先于代码**：能用上游 flag / env 解决的不许开分支。`STRATA_SM75_PERF` 就是例子——它不需要 fork。
4. 代码改动要求**最小、无 env 后门、无探针残留**。S1 的 `+16/−1`（一个判据 + 注释）是范本。
5. 默认路径与上游发布保持字节一致；新行为一律 opt-in、可一键关掉。
6. 每个改动必须写明"**只帮这台机器**"还是"**帮所有 `sm_75` 卡**"。后者按 `CONTRIBUTING.md` 回馈上游，
   合并后 fork 里那条分支应能删除——**分支的存在时间就是维护成本**。
7. 不许动钉死的 ggml pin（`3cf03257`），除非同时给出本机 A/B。#3724 是个现成的候选（§7.1）。
8. 每次 rebase 或换引擎后必须重跑**回归门禁**（§9.2），不跑不许上线。

## 6. "踩着优秀的项目过河"：准入过滤器

### 6.1 可比性核对（先过这一关，再看数字）

必须逐项对齐才允许引用外部数字：模型与规模 / 量化格式 / 并行方式（TP vs 层切分）/ 上下文长度 /
投机方法与命中率 / 输入是合成还是真实 / 度量口径（解码 tok/s 还是端到端墙钟）。

`strata-borrow-vllm2080ti-20261017.md` 已经做到这点（它自己标明对方是 27B NVFP4 合成输入、
与我方 36 GB、24,576 专家的 IQ3_XXS 不可横比）——把这条从个人习惯写成规则。

**补一条**：借倍率之前先借**模型**。服务器已有 `qwen36-q8_0` pack，与 vLLM 那台跑的
Qwen3.6-35B-A3B 同模型族。用它做一次同模型对照，才能把"1.5× / 3.3×"从口号变成可核对的差距。

### 6.2 `sm_75` 可移植性判定（Turing 缺什么）

**不可移植**（看到就走开，或愿意重写）：`cp.async`（sm_80+）、TMA / bulk copy（sm_90+）、`wgmma`（sm_90+）、
FP8 mma（sm_89+）、bf16 mma（sm_80+）、thread-block cluster 与 `setmaxnreg`（sm_90+）、分布式共享内存（sm_90+）、
`redux.sync`（sm_80+）。

**可移植**（Turing 有）：fp16 `mma.sync m16n8k16`、int8 `mma.sync m16n8k8/k32`、`ldmatrix`、`shfl`、
copy-engine / DMA 与计算重叠、pinned host + 分块流水、L2 友好的数据排布。

**需在机器上核实后才能引用（本机可测，当前未测）**：每 SM 可用 shared memory、L2 容量、每线程寄存器上限、
`cudaGraphLaunch` 在本机的实测耗时（对照上游 #3497 报的 1.47 ms）。

### 6.3 来源分级（优先级从高到低）

1. **同型号卡的 fork 与报告**：`weicj/vLLM-2080Ti-Definitive`（双 2080 Ti 22 GB + NV2、TP=2）、
   上游 `bench/results/2026-10-08-community-2x-titan-rtx`（同 `sm_75`、同样无 AVX-512）。
2. **上游自己为老架构做的事**：GP100 / `sm_60` 系列（PR #3752、#3455、#3867）、`STRATA_SM75_PERF` 系列与 #2197。
3. **同代不同卡**（3060 / 3080 / T10）：机制可借，数字不可借。
4. **新架构**（Hopper / Blackwell / RDNA4）：默认不可移植，除非 §6.2 判定通过。
5. **论文与博客**：只当线索，标 *未测*。

每个借鉴项开工前必须写齐六格：来源 / 机制 / `sm_75` 前置条件 / 预期收益区间 / 成本 / 判据与回退。

   本机任何并发都会把单流腰斩，干净 A/B 只能等停机窗口，平时靠它盯显存余量与速度/命中的漂移。

   **重启代价已实测：到 `/health`=200 约 165 s**；该数字用于比较实验成本，不设每天或每轮次数上限。
